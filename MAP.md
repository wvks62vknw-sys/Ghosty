# Ghosty — code map

Read this before changing anything. It says where things live and how to make the most
common changes. Keep changes small, follow the patterns of the neighbouring code, and do
not add npm packages (the build has only TypeScript and esbuild).

## Two halves

| Part | Folder | Runs on | Deploys when |
|---|---|---|---|
| **Interface** | `apps/web/` | your browser (static files served by the Ghosty Worker) | every branch gets a preview; `main` goes live |
| **Brain** | `apps/edge/` | Cloudflare Worker + Durable Object | when a change reaches `main` |
| Shared types | `packages/shared/src/protocol.ts` | both | — |

One Worker (`apps/edge`, config `apps/edge/wrangler.jsonc`) serves both: files from
`apps/web/dist` for every path, and the brain for `/api/*`. The interface talks to the brain
only through `/api/*`. Public data feeds go through `/api/proxy?url=…` (brain caches them).

## Protected kernel (you cannot edit these without the owner unlocking the kernel)

`apps/edge/src/kernel/*` (auth, permissions, vault, protected list) · `apps/edge/src/index.ts`
· `apps/edge/src/agent.ts` · `apps/edge/src/env.ts` · `apps/edge/src/tools/{index,types,repo}.ts`
· `apps/edge/src/github.ts` · `apps/edge/src/keys.ts` · `apps/edge/src/{integrations/mail,tools/email}.ts` · `apps/edge/wrangler*` · `apps/edge/package.json` · build scripts and installer settings (`apps/web/build.mjs`, `apps/*/package.json`, lockfiles, `.npmrc`, `bunfig.toml`)
· `apps/web/public/_headers` · `.github/*`. The exact list is `PROTECTED_PATHS` in
`apps/edge/src/kernel/protected.ts`. New brain tools go in **`apps/edge/src/tools/extra.ts`**
(unprotected), which is registered automatically.

## Room JSON (SPACE PLANNER → 3D STUDIO)

The shape the 3D STUDIO's ROOM pane reads (`apps/web/src/studio/room.ts`, `parseRoom`), all in centimetres:

```json
{ "room": { "w": 400, "d": 300, "h": 240 },
  "items": [ { "name": "Sofa", "w": 200, "d": 90, "h": 85, "x": 20, "y": 200, "rot": 0 } ] }
```

`w` = width (left → right on the plan), `d` = depth (top → bottom on the plan), `h` = height (room 240 and
items 75 when missing). `x`, `y` = the item's **top-left corner** on the plan, from the room's top-left
corner, as drawn before turning; `rot` = degrees **clockwise seen from above**, about the item's own centre.
Room 50 cm – 50 m a side, height 1–10 m, at most 120 items; an item without a positive `w` and `d` is left
out. A bare `{ "w", "d", "h" }` is a room with nothing in it. The planner's export and the brain's
`open_studio` `room` argument use the same shape.

The SPACE PLANNER keeps its own plan differently (quarter turns `rot` 0–3, `x`, `y` = the corner of the
**turned** footprint, the name in `label`). One pure converter, `apps/web/src/space/roomjson.ts`, joins the
two: `planToRoom` (the planner's EXPORT → JSON writes Room JSON: `label` → `name`, `rot × 90`, and for a
quarter-turned piece the corner moved by `((d − w)/2, (w − d)/2)` to the unturned rectangle's corner, plus
the planner's `id` and `kind`), `roomToPlan` (the planner's IMPORT: Room JSON back, turns rounded to the
nearest quarter, or an older planner file as it is) and `isPlannerPlan` (pieces with `label` and no
`name`; `parseRoom` converts those first). Round-trip tested in `apps/edge/test/studio.test.mjs`.

### Room JSON v2: rooms, walls, doors and windows

`packages/shared/src/design.ts`. Everything above still holds (a file without `v` is v1: one box room,
no openings, and the planner writes a plain box room exactly as v1). v2 adds, all optional:

```json
{ "v": 2, "room": { "w": 800, "d": 400, "h": 240 }, "wall": 10, "north": 0,
  "rooms": [ { "id": "r1", "name": "Lounge", "poly": [[0,0],[350,0],[350,120],[500,120],[500,400],[0,400]] },
             { "id": "r2", "name": "Study", "poly": [[500,0],[800,0],[800,300],[500,300]] } ],
  "openings": [ { "id": "d1", "type": "door", "room": "r1", "wall": 3, "at": 40, "w": 80, "h": 200,
                  "hinge": "start", "swing": "in" },
                { "id": "w1", "type": "window", "room": "r1", "wall": 0, "at": 100, "w": 120, "h": 120, "sill": 90 } ],
  "items": [ … as v1 … ] }
```

`rooms[].poly` = corners in cm on the plan (x right, y down), either way round, 3–24 corners, no walls
crossing, at least 50 × 50 cm; up to 12 rooms. `room` = the box round every room (rooms are moved so it
starts at 0, 0, furniture with them). `wall` = wall thickness (2–60 cm, default 10); walls stand outside
each room's floor, so inside sizes are exact; a wall two rooms share is built once, on the line between
them. `north` = the compass bearing of the plan's top edge (0 = north up), for which way windows face.
An opening sits on wall `wall` of room `room` — the edge from corner `wall` to the next — `at` cm from that
corner, `w` wide (≥ 30 cm), at least 5 cm from the corners and from other openings on the wall. A door: `h`
(200), `hinge` `start`|`end` (the near or far side of the opening along the wall), `swing` `in` (into its
room) | `out`. A window: `h` (120) above `sill` (90), within the ceiling. An opening that does not fit is
left out and named (`readLayout().dropped`). The planner stores the same fields on its plan (`rooms`,
`openings`, `wall`, `h`, `north`); `planToRoom` / `roomToPlan` carry them across unchanged (tested in
`design.test.mjs`). The brain's `design_changes` options are whole v2 plans.

## Recipes

**Add a panel to an existing tab** — in `features/<tab>/index.ts`:
```ts
const p = panel('MY PANEL', { footer: true });         // from ui/components
const list = pager(p, 44, (x: Item) => row('LABEL', x.text, x.value));
P.right.append(p.el);                                   // P = page(...) at the top of mount()
myFeed.onChange(() => list.set(myFeed.data ?? []));     // repaint when data changes
```
Return `enter()` that calls `myFeed.start()`.

**Add a data feed** — new file `data/<name>.ts`:
```ts
export const thing = new Feed<Thing[]>('thing', async () => {
  const j = await fetchJson<Raw>('https://api.example.com/x', 300);   // ttl seconds
  return j.items.map(...);
}, 300_000);                                                          // poll interval ms
```
Then add the host to `FEED_HOSTS` in `apps/edge/src/index.ts`, or the proxy refuses it.

**Add a tab** — create `features/<name>/index.ts` exporting a `TabDef`
(`{ id, title, icon: '<svg path markup>', scene: 'backdrop', mount(root) { const P = page(root, {tag:'TITLE'}); …; return { enter(){}, describe: () => '…' } } }`)
and add it to `TABS` in `features/index.ts`. It appears in the dock and palette automatically.

**Add a brain tool** (a new ability) — in `apps/edge/src/tools/extra.ts`:
```ts
export const myTools: Tool[] = [{
  name: 'my_tool', description: 'What it does and when to use it.',
  parameters: { type: 'object', properties: { q: { type: 'string' } }, required: ['q'] },
  risk: 'auto',                        // 'confirm' = owner must approve each use
  async run(a, ctx) { const q = arg.str(a, 'q'); …; return 'text for the model'; },
}];
```
Put it in `extraTools` in `tools/extra.ts` (registered automatically; names must not clash with
built-in tools). Wrap text read from the web with `asData(source, text)` from `../kernel/permissions`.
If it needs a key, add it to `KEYS` in `keys.ts` and read it with `await ctx.vault.get('name')`.

**Make the brain act on screen** — add a command in `commands/builtin.ts` (`register({ id, run })`),
add the name to `CLIENT_COMMANDS` in `packages/shared/src/protocol.ts`, and add a client tool
in `apps/edge/src/tools/ui.ts` with the same name.

**Animate something** — use `onFrame((dt) => …)` from `engine/scheduler.ts`. Never start
your own `requestAnimationFrame` or `setInterval` for animation.

## How a change gets checked

1. `propose_change` / `update_change` run a fast self-check first (`apps/edge/src/selfcheck.ts`):
   missing files or exports in imports, unbalanced brackets, code pasted twice, a name declared twice,
   placeholder comments ("// ... existing code"), a file replaced by a fragment of itself, npm package
   imports, dynamic innerHTML/eval, a new tab not added to `TABS`, a feed host missing from `FEED_HOSTS`,
   bad JSON. A tool call whose arguments were cut off (invalid JSON) is refused before anything runs.
2. CI (`.github/workflows/check.yml`): brain typecheck + tests, interface typecheck + build, the
   Cloudflare build (dry run), and a real-browser run (`tests/*.spec.mjs`: chat, approvals, every
   tab, agenda, radio, app/notifications, and that every tab scrolls instead of cutting off).
   Errors come back as annotations — `wait_for_checks` shows them to you.
3. Shipping needs every check green. After shipping, the deploy is checked and rolled back if it fails;
   anything broken that lands on main by other means is restored by the `guard` job.

## Rules

- Before a self-edit, `study` the matching playbook. After fixing a failed check, `learn_lesson`.

- TypeScript strict. Run `npm run check` in `apps/web` and `apps/edge` (CI does this on every change).
- Build DOM with `h()` and `textContent`. Never put fetched or user text into `innerHTML`.
- No new npm packages, no external `<script>` tags (the security policy blocks them).
- Small, focused changes. One feature per change. Explain it in the change summary.
- Keep `MAP.md` accurate when you add files or move things.
